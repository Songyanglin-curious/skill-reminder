# 学习资料维护与轮末补漏

本规则只保存**教学已经确定或实际发生**的变化。教学是否继续、阶段是否成立、总结怎样组织由 [教学规则](teaching.md) 决定。维护不重新授课、不替教学作判断；轮末 Hook 只检查遗漏。

## 何时写、写到哪里

普通非学习任务、用户要求不记录、无实质变化或已经保存时直接结束。存在遗漏才按 [资料规格](spec.md) 从已确认工作区定位相关专题，读取目标文件最新内容：

- **专题计划已建立或路线已修订**：保存独立专题计划或更新同一份既有计划，补齐导航；不把路线写进进度。
- **状态改变**：当当前阶段、问题、关键证据、缺口、接续点或阶段的完成、暂挂、跳过状态变化时，更新进度快照。计划重排、改名或合并时，保存教学已经确认的状态，并将快照中的阶段引用指向现行计划。切换专题时保留尚未结束专题的简短接续信息或成果链接。已解决的临时分支从活跃缺口移除，不逐轮追加历史。
- **阶段或专题已产出综合**：保存实际形成的成果，复用适合的已有文件；阶段收束但尚未形成总结时，不由维护或 Hook 代写。一次讲解或补缺结束本身不触发写笔记。
- **资料与实际状态不符**：以可确认的学习事实和现行计划修正必要引用或状态。区分已讲解、自述理解、解释或判断证据和独立应用证据。Agent 运行示例只证明观察到的程序行为；没有学习者反馈时，进度最多记为已讲解、理解待确认，接续点留在待确认的当前问题。

## 写入边界

只维护已授权工作区内的相关资料，按实际变化做最小修改，回读内容和相关链接；路径或权限无法确认、写入失败时说明未完成，不猜测、不反复重试。未经用户同意不重组、迁移或删除重要资料，不覆盖长期目标和范围。不要修改插件源码、默认规则、用户规则或 DSH 配置，不安装插件或提交 Git。

没有遗漏时直接结束；有写入时只说明有意义的变化，不生成检查流水。不要因为维护或 Hook 另开阶段、追加评测、生成教学总结、重新初始化或再次请求续接。
