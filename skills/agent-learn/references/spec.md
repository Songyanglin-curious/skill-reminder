# 学习工作区与资料规格

资料保存在用户指定且已授权的学习工作区，不写入插件目录或项目开发 Docs。一个专题是围绕已确定目标开展的一段学习；独立专题计划是它的主要入口，进度与成果应能定位到同一份计划。

## 工作区启用

DSH 会话的 cwd 应指向学习工作区根目录。自动检查只覆盖本轮调用过 `agent_learn_rules(mode="teaching")` 的专题教学，并检查当前 cwd 下的 `.agent-learn.json` 和 `index.md`，不向父目录查找、不扫描其他领域。标记为：

```json
{
  "version": 1,
  "enabled": true
}
```

标记只表达启用状态，不保存学习数据。设为 false 可关闭自动检查，不影响正常教学和显式规则入口。版本不符、标记损坏或缺少根索引时不自动修复或初始化。

## 学习资料的层级

这棵树描述资料的职责和归属。文件名与目录按工作区的现有习惯和实际查阅需要组织。

```text
领域
├── 领域计划
├── 领域进度
└── 专题
    ├── 专题计划
    ├── 阶段成果
    ├── 专题最终总结
    └── 必要的知识资料
```

## 资料职责

| 资料 | 回答的问题与必要内容 |
| --- | --- |
| 领域计划 | 整个领域怎么学？保留领域目标、大致方向和专题入口，不承载各专题的详细路线。 |
| 专题计划 | 为达成这个目标，目前应该怎样学？独立文件保存目标、已有基础、范围、能解释各部分关系的整体知识模型、由模型推导的教学路线及成果设计。详略随专题展开，建立与修订见[专题规划规则](planning.md)。 |
| 领域进度（`progress.md`） | 现在在哪里、从哪里继续？链接当前专题计划，简记当前阶段、实际问题、关键证据和未解缺口、必要的分支返回点及一个接续动作。简记已完成、暂挂、跳过的阶段，或链接到能确认这些状态的成果。不复制计划、总结或学习流水。 |
| 阶段总结 | 这个阶段建立了什么理解？重建该阶段的知识结构、关键关系和适用边界，区分已有证据和未验证处。 |
| 专题总结 | 整个专题形成了什么知识模型？对照现行专题目标，把阶段成果重新综合为能独立理解和使用的整体，不按阶段原样拼接。 |

知识笔记、案例、图示和实践结果只在有复用价值时单独保存；已存在且适合承载的资料优先复用。计划可以记录规划依据中的初始基础，学习中取得的动态证据留在进度或成果。不要把计划中的练习写成已完成证据。

用现行计划中的阶段名称或稳定链接定位阶段，避免只写会随路线重排变化的序号。暂挂时简记待补内容或返回条件；跳过时按实际决定记录。旧进度没有阶段状态时，只依据可确认的记录补齐，缺少依据的阶段保留为未确认。

## 导航与组织

根 `index.md` 导航到领域，领域索引能定位领域计划、进度及专题资料。保留已有 `plan.md`、`progress.md` 等有效入口和命名，独立专题计划应有唯一可导航入口。按需新增资料目录，并为新目录建立 `index.md`，只索引直接子级。阶段、临时分支与尚未产生的成果无需预建文件。

阶段成果与专题最终总结各有职责，可以放在同一文件的不同小节。以 Java 正则为例，阶段总结较短时，两份内容文件就够用。索引按上面的导航规则维护。

```text
Java正则/
├── 计划.md
└── 总结.md
```

`计划.md` 承载专题目标与路线。`总结.md` 随学习进展记录各阶段的成果，专题收束时再增加最终综合。以后有独立查阅需求时，再拆分成果或补充知识资料。

已有路线若分散在领域计划或进度中，按需从所学专题提取、补齐，不扫描或重组其他资料。证据注明实际来源与不确定性，教程示意、讲解内容和用户表现不能互相代替。
