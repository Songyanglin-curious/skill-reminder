# 阶段教学与综合

## 恢复路线

先读现行专题计划，结合进度与已形成的成果确定当前阶段、实际问题、理解证据、缺口和下一步。说明当前问题如何服务阶段目标、为后面什么打基础。若用户要持续学习且尚无专题计划，先按[专题规划](planning.md)建立计划。有写入授权时保存为独立文档并接入导航，再据此开始。正常接续沿用现行路线；课题变化时再调整计划。

## 组织一批相关内容

1. 从计划中选一个当前问题，明确这批讲解要让学习者能解释、判断或完成什么。按用户基础与目标深度，将共同支撑该判断的概念、例子和边界组织在一起。例如，用一次教学对照字面字符串操作、正则匹配、结构解析和业务语义，帮助学习者判断一个文本处理需求该用什么。
2. 先说明整体问题与关键关系，再展开必要机制和反例。复杂结构可用图或交互演示帮助理解，依据当前问题选形式。
3. 补齐当前判断还缺的必要环节。当前问题讲完整后保留一个接续点，等待学习者的反馈、追问或明确继续。一次完整教学可以跨多轮；轮末维护或宿主自动续接不能代替学习者的反馈。用户明确要求连续推进时按指定范围继续，完成状态仍以实际证据为准。

## 递归补缺与路线修订

- **局部理解卡点**。定位它在哪一步阻碍当前问题，针对性补解释、示例或验证。必要时继续向下补前置；补到足以解决这一层问题后逐层返回，用新理解重新处理原来的问题。中途暂停时记录未解缺口和返回点。
- **路线问题**。新证据表明前置缺失、次序失当、阶段需要合并或原路线达不到既定深度时，按[专题规划](planning.md)修订同一计划，保留仍有依据的状态，注明受影响阶段与待确认部分，再更新进度并按新路线继续。目标、范围或目标深度变化由学习者决定。

## 阶段与专题综合

用计划的阶段目标和实际理解判断收束。必要时用与目标相称的预测、反例、判断或实践取得证据，跳过或暂挂的阶段保留真实状态。工具执行的结果可以证实程序行为；判断学习者能力需要学习者本人的表现。

- **阶段收束**。围绕阶段核心问题重建本阶段的模型和关键关系，再说明机制、例子、适用边界与剩余缺口。完成综合后按计划和用户意图安排接续。
- **专题收束**。以现行专题计划和原定学习目标为骨架，重新组织各阶段实际成果，解释各部分怎样共同回答专题核心问题，给出适用边界、验证与仍有的缺口。用户中途要求总结时，综合已有成果并保留未完成状态。

先让学习者得到能独立理解的综合，再按[资料维护](maintenance.md)保存已经形成的成果。用户要求不记录或无法落盘时，在对话中交付综合。
