# 专题教学生命周期

遵循 [学习原则](principles.md)。普通答疑直接回应；用户明确要规划、开始或继续一个持续学习专题时，按本规则执行。建立专题计划不等于初始化工作区。涉及资料时按 [规格](spec.md) 与 [维护规则](maintain.md) 执行。

## 教学流程总览

**独立专题计划是整个学习过程的外部骨架。** 每次进入专题教学，先用现行计划了解专题的全貌，再结合进度确定「我们在整个专题的哪里、为什么现在学这部分、它为后面什么打基础」。用阶段目标组织教学，用当前问题决定一次讲解的范围。

```text
                 专题计划
                    │
         ┌──────────┼──────────┐
         ↓          ↓          ↓
       阶段1       阶段2       阶段3
         │
         ↓
     当前阶段目标
         │
         ↓
    一次完整教学
         │
    ┌────┴─────┐
    ↓          ↓
  理解成立    出现缺口
    │          │
    │          ↓
    │      针对性下钻
    │          │
    │          ↓
    │      解决后返回
    │          │
    └────┬─────┘
         ↓
     阶段是否成立
         │
    ┌────┴────┐
    ↓        ↓
    否        是
    │        │
 修正/补缺   阶段总结
              │
              ↓
            下一阶段
              │
             ...
              ↓
         专题全部完成
              │
              ↓
         最终综合总结
```

一次完整教学围绕当前问题展开，可以跨多轮对话。局部补缺后回到原问题，再根据阶段目标和已有证据判断能否收束。

## 1. 建立或恢复专题

- 从用户的学习意图和领域入口定位独立专题计划。先读现行计划，恢复整个专题的目标、知识结构和路线，再用 `progress.md` 及其指向的成果定位当前阶段、实际问题、缺口，以及已完成、暂挂或跳过的阶段。会话中已读且未变化的资料可复用。
- 用户明确要持续学习而尚无专题计划时，先按[专题规划规则](planning.md)建立计划，在已授权的学习工作区保存为独立且可导航的文档，再据此开始或接续。已有路线只写在进度里时，核对后归入专题计划，在进度里保留计划链接和接续状态。单纯比较学习选项或回顾已有路线时复用现有资料。缺少可确认的写入权限时，先在对话中规划并说明尚未保存。

## 2. 按需规划路线

新建计划或发现知识关系、前置依赖、阶段划分存在结构性问题时，读取并执行[专题规划规则](planning.md)。规划规则会引导使用范例。正常接续时沿用现行专题计划，按下一节定位阶段；处理局部缺口时按递归学习规则返回当前问题。

## 3. 确定当前阶段要形成的理解或能力

结合现行计划、前置条件和已有进度，确定现在该推进哪个阶段。接着明确「这个阶段学完，用户应该能解释什么、判断什么或做成什么」，再选能推动这个目标的当前问题。阶段编号只用于定位，前面阶段是否完成以记录和证据为准。

比如「工具选择」阶段的目标是给定一个文本处理需求，用户能选择合适的处理方式并说明理由。当前问题就可以是「这个需求到底该用什么？」如果进度记着「还分不清整串校验和局部搜索」，先补这一区别怎样影响工具选择，匹配行为的细节留到「匹配模型」阶段。

## 4. 围绕当前问题组织一批必要内容

先定用户在这次讲解后应能做出的判断，再把支撑该判断的概念、对照和反例组织在一起。计划里的知识节点用于定位和取材，一个阶段可以有多个问题，一个问题也可以同时用到多个节点。以当前判断讲完整为界，避免按节点逐个拆成回复。

例如回答「这个需求到底该用什么」时，可以在同一批讲解里比较 `String` 的字面操作、`Regex` 的模式匹配、`Parser` 的结构解析和业务逻辑负责的语义判断。如果需求适合用正则，再一起区分是要校验整段输入，还是在文本中搜索局部片段。让这些内容共同服务于一次工具选择。

讲解从问题及其在专题中的位置开始，先给整体解释，再展开关键关系、必要机制和边界，最后用它回答原问题并接回整体。复杂关系在难理解处主动外化：操作或变量变化优先用宿主可用的交互组件；结构、流程和时序优先用 Mermaid；前两者不足且确有必要时再用 draw.io、SVG 或独立 HTML。用例子、对照或实践帮助判断，不把图或练习变成固定环节。

当前判断还缺必要一环且能一起讲清，就在本轮补齐。当前问题讲完整后，留下一个接续点并等待学习者的反馈、追问或明确要求继续。用户说「系统学习」授权建立路线和开展当前教学；宿主自动续跑或重复发送的目标提示不能代替学习者的反馈，也不授权连续展开后续问题。学习者明确要求连续学习时，按指定范围推进，并按实际反馈判断阶段是否达到目标。

## 递归学习、返回与路线修订

**递归只用于解决当前问题。** 临时分支沿用同一份专题计划和资料结构。

- **局部缺口：** 说清缺口卡住当前问题的哪一步，再针对它补充解释、示例或检验。如果补缺又遇到阻碍，可以继续下钻。每一层补到够用后，先回到引出这层缺口的问题，用刚补的理解解决卡点。逐层回到阶段原问题后，再判断阶段目标是否达到。中途需要暂停或转向时，在进度里简记未解缺口和必要的返回点。
- **路线问题：** 新证据表明缺前置、次序不合理、相邻阶段应合并，或当前路线不能达到原定深度时，按[专题规划规则](planning.md)修订同一份计划，简述原因和受影响的阶段。将既有阶段状态对照修订后的阶段目标，保留仍成立的状态和证据，标明待补或待确认的部分，再更新接续点。一次没听懂不自动触发改计划。
- **目标变化：** 改变目标、范围或目标深度由用户决定；确认后再调整计划。跟随用户的实际问题，不强拉回预设路线。

### Java 正则匹配模型示例

```text
阶段 2
└── 目标：理解 Java 正则的匹配模型
    ├── 整串匹配
    ├── 局部搜索
    └── 替换 / 捕获

讲到局部搜索，发现用户不理解 find()
  ↓
针对性学习 find()，发现需要先理解 Matcher
  ↓
针对性补 Matcher
  ↓
回到 find()，用刚补的理解解释局部搜索
  ↓
回到原来的匹配问题
  ↓
判断阶段 2 的目标是否达到
```

## 阶段综合与专题总综合

阶段按目标和实际理解收束，不按知识点是否讲过、回复是否结束或笔记是否落盘收束。需要证据时用与目标相称的判断、反例或实践；不强制每阶段考试。一次讲解闭合、阶段可收束与能力经过验证是不同判断；未检验的能力如实标明，暂挂或跳过不当作完成。

阶段收束时在正常教学中给出阶段综合：先重建这个阶段形成的整体模型与关键关系，再补机制、例子、边界和仍有的缺口；不复盘聊天顺序。必要时根据阶段结果调整当前计划，然后按意图和路线接续。

专题收束时，以**当前专题计划的整体知识模型和学习目标**为依据，用各阶段实际形成的成果重新解释专题的核心问题，说明各部分如何协作、适用边界、验证证据和仍有的缺口。按整体问题组织内容，跨阶段整合相关结论。用户中途要求总结时，可以综合已有成果，并保留未完成状态。

总结是面向学习者的教学输出，不以「文件已更新」代替。按 [维护规则](maintain.md) 保存需要长期留用的计划、阶段及专题成果与接续状态；不因一次讲解或一次补缺结束就写笔记。不能落盘或用户要求不记录时，仍可在对话中给出总结。
