# 实践经验与验收

## 从实际使用中得到的经验

- **进度和成果各有用途。** 旧版有一次 Godot 学习在准备转入下一单元时更新了进度，却遗漏主题笔记。旧 0.1.2 将单元收束列为写笔记的时机。现在的规则把判断放回教学流程，教学形成阶段或专题综合后保存成果，轮末维护只补写已形成的内容。验收时分别查看接续点是否准确、已经形成的成果是否保存且可从索引找到。[旧版问题与修复记录](https://github.com/Songyanglin-curious/agent-learn/blob/dc9f6bb3ba4e45fc674e48eeed1ff3f0f888a9ba/docs/project/开发与验证.md#012-修复验证2026-11-17) [现行维护规则](../references/maintain.md)
- **把协议证据和教学证据分别记录。** 旧 DSH 的独立包测试、宿主服务测试和隔离 Profile 安装验证覆盖了包内容、工具注册与会话投递。旧 Codex 在临时工作区用关闭 Hook 的对照运行核实了同轮续接。判断教学质量还需要观察实际学习对话及写入的资料，包括用户的追问如何处理、阶段判断有无依据，以及新会话能否接续。[开发与验证记录](https://github.com/Songyanglin-curious/agent-learn/blob/dc9f6bb3ba4e45fc674e48eeed1ff3f0f888a9ba/docs/project/开发与验证.md)
- **按实际入口验证交付。** 旧 DSH 在隔离 Profile 中用宿主加载安装产物，并核对配置、包内规则和哈希。直接用 Node 导入曾因缺少宿主依赖解析而失败。旧 Codex 则在安装后核对 Skill 和 Hook，审阅信任后用新聊天复查。迁移共享 Skill 时同样从实际宿主入口核对加载路径和提醒来源。[旧 DSH 交付记录](https://github.com/Songyanglin-curious/agent-learn/blob/dc9f6bb3ba4e45fc674e48eeed1ff3f0f888a9ba/docs/project/开发与验证.md) [本仓库验证入口](../../../README.md#验证与迁移)

## 可复用的真实会话验收场景

以下场景来自旧项目待验收记录，采用当前共享 Skill 的入口与提醒行为。实际结果以运行时的学习对话和落盘资料为准。[agent-learn 原验收清单](https://github.com/Songyanglin-curious/agent-learn/blob/dc9f6bb3ba4e45fc674e48eeed1ff3f0f888a9ba/docs/pending/index.md)

- **新专题规划**。选一个范例之外的专题，只给学习目标与已有基础。检查能否形成独立、可导航的计划，解释阶段顺序，给出可直接开始的问题，并在后续阶段用同一核心认识解释新的现象或解决新的问题。
- **轻量专题和局部追问**。围绕一个完整判断展开相关知识。出现追问时补到够用，按对话意图回到原问题。核对短计划、实际形成的成果和接续点是否足够支持下次恢复。
- **复杂专题与路线调整**。暂挂或跳过一个阶段，完成后续阶段后重排计划。检查新会话能定位实际阶段状态和接续点，阶段综合与专题总结能分别解释各自的问题。
- **提醒与写入边界**。在启用提醒的工作区完成普通答疑、已有资料同步的学习轮次，以及确实漏记成果的学习轮次。分别检查前两种场景无需写入，第三种只补齐已发生的变化。停用提醒后再核对投递状态。
