# Agent Docs

## 1. 核心目标

Docs 是人和 AI 共用的持久上下文／共享记忆，用于恢复理解并继续工作。

本 Skill 负责让项目知识能够持续积累、被正确理解、方便查找，并随着实际项目和已确认的认识变化而更新。

核心目标不是记录工作过程，而是维护一套可信、可理解、可导航的项目知识。

Docs 的四个核心领域：

- **Project**：当前实际软件系统的定位、能力、行为、组成、职责及其重要关系。
- **Design**：需求、设计输入、参考依据、方案、决策及有价值的演变。
- **Rules**：项目中持续适用的规范、约定、约束和偏好。
- **Knowledge**：原理、方法、工程经验及值得长期保留的知识。

具体内容归属以 `principles.md` 为准。

## 2. 专业规则体系

`references/` 中的四份原始规则是本 Skill 的专业执行依据。

**不得为了精简 Skill 而重新概括、替代或削弱原规则中的执行要求。**

| 规则 | 负责内容 |
|---|---|
| `references/principles.md` | Docs 目标、组织原则、模块职责、内容归属 |
| `references/spec.md` | 目录结构、索引规范、Project 内容规格、文档质量 |
| `references/init.md` | 初始化操作、已有项目接入、Project 建模、初始化验收 |
| `references/maintain.md` | 日常维护判断、模块准入、修改权限、维护步骤及验收 |

### 规则加载原则

根据当前任务加载所需规则，不要求每次读取全部文件。

| 任务 | 必须读取的规则 |
|---|---|
| 判断资料应该归入哪个模块 | `principles.md` |
| 新建、修改或检查文档结构与索引 | `principles.md`、`spec.md` |
| 初始化或接入 Docs | `principles.md`、`spec.md`、`init.md` |
| 建立或重建 Project 系统映射 | `principles.md`、`spec.md`、`init.md` |
| 日常 Docs 维护 | `maintain.md`，根据涉及内容读取 `principles.md`、`spec.md` |
| 专项审查 Docs 质量 | `principles.md`、`spec.md`，按审查目标读取其他规则 |
| 普通查阅已有 Docs | 从项目索引按需查阅，不必加载全部规则 |

已经读取且没有变化的规则可以在当前上下文中复用，不必重复读取。

## 3. 工作模式识别

### 3.1 项目知识查阅

当任务需要利用已有项目知识时：

1. 从项目根目录 `AGENTS.md` 获取 Docs 入口。
2. 阅读 `docs/index.md`，理解知识组织。
3. 根据当前任务进入相关模块索引。
4. 只读取解决当前问题所需的具体文档。
5. 涉及当前实现时，以代码、配置和可核实行为为依据验证。

不要求每次阅读全部 Docs。

### 3.2 Docs 设计与讨论

当用户要求讨论 Docs 结构、分类、维护方案或设计原则时：

1. 阅读相关专业规则。
2. 根据现有 Docs 和实际项目情况分析。
3. 识别问题、影响和可行调整。
4. 给出建议及必要的取舍。

**讨论、分析和提出方案不等于授权修改文件。**

用户没有明确要求实施时，只分析，不修改。

### 3.3 Docs 初始化与接入

仅当用户明确要求初始化、接入或改造 Docs 时，执行 `init.md`。

按照其中规定的检查、范围确定、基础结构建立、Project 建模和验收流程执行。

不得把日常维护提醒当成初始化授权。

已有 Docs 如果已经满足目标，复用现有结构，不重复初始化。

### 3.4 日常维护

当收到 `skill-reminder` 的 Docs 维护提醒，或者用户明确要求维护 Docs 时，执行 `maintain.md`。

以本轮实际发生的变化为依据：

1. 识别值得持久化的项目事实、设计认识、长期约定和知识变化。
2. 根据变化类型判断哪些模块需要检查。
3. 定位受影响的已有文档。
4. 判断是否需要更新、创建或不作处理。
5. 在授权范围内执行修改。
6. 更新必要的索引并核对结果。

Hook 只是提醒入口，不代表必须修改文件。

没有实质变化时直接结束。

### 3.5 指定内容更新

用户明确要求记录、更新、修正或整理某项内容时：

- 按 `principles.md` 判断内容归属。
- 按 `spec.md` 确定组织和编写方式。
- 涉及现有资料的迁移、删除、合并或重要结构调整时，遵守 `maintain.md` 的权限要求。
- 优先更新已有资料，不为同一内容制造重复副本。

## 4. 核心工作原则

### 4.1 Docs 是知识映射，不是工作日志

优先维护能够帮助未来恢复理解的内容：

- 当前项目实际是什么样。
- 为什么形成当前设计。
- 哪些长期约定需要遵循。
- 哪些知识和经验值得保留。
- 当前有哪些需要延续的事项。

不要求记录所有对话、每次修改和中间操作。

### 4.2 Project 必须反映真实系统

Project 是 Docs 中最重要的项目认知模型之一。

它必须以实际实现为依据，以主要能力及其行为为主线，说明系统组成、职责和重要关系，并提供真实代码定位。

不能将以下内容当作合格的 Project：

- 仅介绍项目用途的简单概览。
- 仅罗列工程、目录和文件的结构清单。
- 将各个模块孤立介绍，却没有表达它们如何协作。
- 将 Design 中尚未实现的方案写成当前能力。
- 将调查过程和开发历史拼接成项目说明。

首次建立或明确要求重建 Project 时，严格执行 `init.md` §4.4 的两轮建模方法：

1. 第一轮建立系统全貌，识别主要能力、组成、边界和待查入口。
2. 第二轮围绕主要能力调查实际行为，沿真实入口追踪输入、处理、结果、状态、关键分支和模块协作。
3. 综合调查结果，建立共享对象、状态、职责、交接和约束的整体模型。
4. 按 `spec.md` §4.6 检查覆盖完整性、表达充分性、整体一致性、事实准确性和实现导航。

日常维护不重复进行全量建模，只检查本轮变化影响的范围。

### 4.3 索引是知识导航，也是认知入口

索引不能退化为文件列表。

应当帮助读者理解当前范围、主要内容、重要关系和查找路径。

遵循以下导航关系：

`AGENTS.md → docs/index.md → 各级 index.md → 具体文档`

每个实际存在的 Docs 目录都应有 `index.md`。

新增或修改内容时，维护直接父级索引，并沿受影响的上层导航检查，确保新增内容从根索引逐层可达。

具体编写和检查标准以 `spec.md` 为准。

### 4.4 维护当前认知，而不是不断追加文档

当项目发生变化时：

- 更新已经失效的现状描述。
- 修正不准确的职责和关系。
- 更新受影响的代码定位。
- 保留仍然有效的设计背景和历史价值。
- 避免通过不断新增文档代替对原有知识的修正。

内容应有明确的主要维护位置，其他文档通过引用建立联系。

### 4.5 修改必须有事实依据和权限边界

严格区分：

- 当前实际实现。
- 已确认的设计决定。
- 尚未决定的候选方案。
- 已验证的事实。
- 尚未验证的认识。

不把推测写成事实，不把讨论中的想法写成决定。

日常维护可以直接执行规则允许的常规更新，但不能擅自迁移、删除、合并重要资料或重组整个目录。

具体权限以 `maintain.md` 和用户当前授权为准。

## 5. 执行边界

- 不因为 Skill 被调用就自动初始化 Docs。
- 不因为 Hook 提醒就扫描整个仓库或全部 Docs。
- 不要求每轮都产生文档修改。
- 不为了补齐目录或索引形式制造空文档。
- 不机械迁移已有的有效资料。
- 不将 Docs 变成开发日志、聊天记录或 Git Diff 日志。
- 不擅自修改项目源码、配置和 Git 状态。
- 不在日常维护中修改本 Skill 的专业规则或插件配置。
- 不启动独立 Agent 执行日常维护，不生成无必要的检查报告。

用户明确提出专项审查、全面重建或其他超出日常维护的任务时，按其授权范围执行，不受日常维护的局部检查范围限制。

## 6. 完成与退出

根据任务类型结束工作：

**查阅任务**
- 提供找到的有效信息及必要的来源、实现位置。
- 不产生无关文档修改。

**设计讨论**
- 提供问题判断、设计建议及影响。
- 未获实施授权时不修改文件。

**初始化任务**
- 按 `init.md` 验收。
- 说明新建、修改、复用内容及未解决问题。

**日常维护**
- 没有需要保存的变化：直接结束。
- 完成维护：简短说明实际修改的文件及主要内容。
- 需要用户决策：说明具体问题和影响，不擅自执行。
- 遇到阻碍：说明未完成范围，不伪称通过。

**专项审查**
- 按用户指定范围检查。
- 区分已确认问题、潜在风险和无法验证的部分。
- 未明确要求修复时，不自动修改。

---

**核心原则：Docs 服务于理解与延续；Project 描述当前系统，Design 解释设计认识，Rules 约束持续行为，Knowledge 积累可复用的知识。调查以实际实现为依据，维护以真实变化为驱动，索引负责让知识可达。**
