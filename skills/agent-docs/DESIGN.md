# Agent Docs 设计

Docs 保存人和 AI 能在另一回合重新获得的项目理解。根 `AGENTS.md` 给出入口，各级索引概括直接子级的范围、关系和查找用途。读者从当前问题选择下一跳，既能从系统全貌深入，也能定位某项行为或决策的依据。

## 四类知识和验证证据

Project 是当前实际系统的映射，主要单位是能力及其实际行为。Design 按设计问题保留需求、外部约束、候选方案、决策理由和重要演变，允许尚未形成结论。Rules 记录在项目里反复生效的规范、约束和偏好。Knowledge 保存对人的理解和学习有价值的原理、方法与经验，也能被 Agent 查阅。归属取决于内容在项目中的作用；同一主题可以通过引用连接其设计依据和实际行为。

Evidence 保留可用于核对的原始材料，Docs 说明结论、适用范围和已验证边界。测试或截图的保存和保留周期按项目约定决定，默认根目录 `evidence/` 仅在形成材料时建立。存量项目优先保持有效入口并通过链接接入；默认四模块也可以只保留索引，直到有内容。

## Project 的调查与维护

建模先通过界面、接口、后台机制、数据、实现和既有资料调查全貌，形成可修订的主要能力清单。再通过关键业务活动追踪触发、处理、结果及会改变判断的分支，找出跨模块交接、共享状态和限制。将调查结果综合成可阅读的系统模型，经索引连接真实实现。通过场景问答检验文档足以支撑正确判断，并另行核对主要能力覆盖。

现状描述随新事实修订。新功能、联调和运行观察可改变项目认知，即使当天没有修改代码，也可能需要核对受影响的能力、关系和整体介绍。先调查，再综合，最后用证据验证表达；已有准确描述时结束。在既有项目中，局部修订优先落在原主题，生命周期提醒把检查交给当前 Agent 及其已有上下文。显式初始化、日常维护与重要结构变更各有对应的授权范围。
