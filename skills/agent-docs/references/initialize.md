# 初始化或接入 Docs

用户明确要求建立、接入、恢复或改造 Docs 时使用。仅询问方案或归属时交付分析。

1. 确定项目边界和主要子工程，检查 Git 状态、工作区改动、现有 `AGENTS.md`、Docs、相关入口与规则。盘点本次指定资料，结合项目实际用途判断归属。保留有用的现有内容、索引与引用。
2. 确定需要新建、增补和复用的内容。首次建立时，按[组织与导航](organization.md)增补根指引、Docs 根索引与四个模块索引。有用的存量组织优先原位接入。已有同等入口的项目只修复明确缺口。
3. 已有实现时按 [Project 建模](project-model.md)调查全貌及主要能力的实际行为，综合并核对当前映射。尚无实现的项目可仅建立空模块索引。覆盖不足时说明实际完成范围，必要的跨会话事项接入已有任务入口。
4. 检查项目代码注释规范。没有同类约定且无冲突时，在 `docs/rules/` 补一条默认约定并接入索引。注释优先简洁、准确的中文，专业术语、API 或代码符号可保留原文，说明意图、约束和不直观的行为。已有同等约定沿用，冲突由用户决定。
5. 核对 [Evidence 约定](organization.md#evidence)，复用已有位置或登记项目根的 `evidence/` 供有材料时使用。

基础导航、核实后的 Project 内容和不冲突的增补可在初始化授权内直接执行。重要既有资料的覆盖、迁移、合并、重命名或删除，顶层重组及长期约定冲突需明确授权。等待决定时可先完成互不依赖的部分。提交、暂存或清理工作区由独立请求授权。

回读本次内容，检查根入口、各级索引、已有资料、证据位置与 Project 质量。报告新增和复用的内容，以及未完成或待决定的事项。
