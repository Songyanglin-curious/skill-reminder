# 接入与维护注意事项

## 共享 Skill 与轮末提醒

旧 `agent-docs` 独立插件在当前 cwd 检查 `docs/index.md`，DSH 通过 `agent_docs_rules` 提供显式入口。共享方案由 `skill-reminder` 从会话目录寻找最近的 Git 根，无 Git 时使用会话目录，并读取该处 `.skill-reminder.json` 的 `skills.agent-docs` 开关。开关启用后，Hook 可以投递短提醒，当前 Agent 按 Skill 查阅项目入口、判断是否值得写入并执行维护。项目没有 `docs/index.md` 时，日常维护在规则层结束。迁移时先核对实际加载的同名 Skill 和投递来源，切换成功后按安装情况停用旧提醒。[旧插件实现](https://github.com/Songyanglin-curious/agent-docs/blob/6465c475657d4d50785ae0954ae4a364a0cb9b19/docs/实现说明.md) [配置定位](../../../src/workspace-config.mjs) [提醒组装](../../../src/reminders.mjs) [共享 Skill](../SKILL.md) [迁移说明](../../../README.md#验证与迁移)

DSH 按会话轮次去重并排除已取消和子 Agent 的回合。Codex 依赖 `stop_hook_active` 防止同一轮反复续接。提醒由启用的 Skill 文案与通用文案组成，实际判断和文档写入仍由当前 Agent 完成。[DSH Hook](../../../src/index.mjs) [Codex Hook](../../../src/codex-stop.mjs) [Docs 提醒文案](../../../prompts/agent-docs.md)

## 初始化和存量接入

用户明确要求初始化、接入或改造时，从现有入口、资料和代码判断需要建立什么。新建 Docs 可从四目录和索引起步。已有实现时，按实际代码和可核实行为建立系统映射。已有可用的文档和组织优先复用，重要资料的搬迁、合并或删除按明确授权处理。[初始化指南](../references/init.md)

索引先改直接父级，再检查上层摘要是否失准。长期使用的外部资料集合由 `AGENTS.md` 提供入口，特定主题的契约或原件就近引用，日志和截图按证据位置查找。验证材料优先沿用项目约定，缺少约定时可在实际产生材料后使用项目根的 `evidence/`。临时输出和需共享、追溯的材料分别按其用途确定 Git 跟踪方式，正式测试和夹具留在工程中。[结构与编写规范](../references/spec.md) [原规则调整预案](https://github.com/Songyanglin-curious/agent-docs/blob/6465c475657d4d50785ae0954ae4a364a0cb9b19/docs/规则调整预案.md)

## 日常维护以本轮事实为起点

- 先判断本轮是否产生值得持久化的变化，再读相关主题。仅完成联调、测试或运行观察也可能改变 Project 的事实。沿本次影响追踪行为、状态、职责和上下游交接，已有内容准确时结束。[维护指南](../references/maintain.md)
- Design 记录已形成的方案及其状态。提炼 Rules 时核对用户的长期约定或同一项目中有充分依据的稳定偏好，保留原有适用范围与约束程度。规则冲突或扩大范围时先确认。[维护指南](../references/maintain.md)
- 按受影响范围回读本次文档与链接。日常维护使用已有验证结果，明示仍待验证的行为。系统性重建或独立语义验收在专项任务中进行。[Project 质量要求](../references/spec.md#46-project-的质量要求) [实践经验与验收](实践经验与验收.md)
