# 实践经验与验收

## Project 系统映射的实践

0.1.7 交付期间，仿真工坊的 Project 文档经过实际修订，用户反馈现有说明有明显改善、已足够使用。交付记录包含这次使用反馈、自动测试、归档核对和安装回读，三场景独立语义验收在当时尚未执行。[仿真工坊反馈与验收记录](https://github.com/Songyanglin-curious/agent-docs/blob/6465c475657d4d50785ae0954ae4a364a0cb9b19/docs/开发与验证.md)

专项验收可以先依据源码、配置和可取得的运行结果建立独立事实依据，再让建模者按正常输入工作。阅读环节用隔离上下文，只给生成的 Project 和问题，比较答案及引用位置与事实依据，并另外以主要能力清单核对覆盖。选择会改变实际判断的问题，例如切换页面后的实际写入目标、草稿何时保存、回执成功或超时意味着什么。[原语义验收方案](https://github.com/Songyanglin-curious/agent-docs/blob/6465c475657d4d50785ae0954ae4a364a0cb9b19/docs/安装与测试.md#project-当前系统映射的语义验收)

| 场景 | 要观察的结果 |
| --- | --- |
| 正向维护 | 只确认联调事实，代码没有改动。已有 Project 缺漏或失实，检查是否沿受影响的能力、行为和关系修正文档。 |
| 负向维护 | 同样的实现和联调事实，Project 已准确说明相关行为，检查是否能直接结束。 |
| 陌生项目初始化 | 给出有实现的陌生项目，检查能否建立覆盖主要能力、解释真实行为、可定位代码的系统映射。 |

手动提醒可以验证规则执行。自动触发需要另外观察宿主投递，真实模型的建模和维护则要看产物与独立阅读结果。日常维护继续使用当前 Agent 和本轮已经掌握的依据。[原语义验收方案](https://github.com/Songyanglin-curious/agent-docs/blob/6465c475657d4d50785ae0954ae4a364a0cb9b19/docs/安装与测试.md#project-当前系统映射的语义验收) [维护指南](../references/maintain.md)

## 双端轻量插件的交付经验

- **验证独立安装产物。** 在干净暂存区构建，从真实归档解压并检查 manifest、Hook、脚本和引用资源。重复打包时关注已删除或改名的文件是否残留。Windows 端曾因用户目录映射导致 Hook 入口判断失效，测试需覆盖实际启动路径及目录映射。[原交付规范](https://github.com/Songyanglin-curious/agent-docs/blob/6465c475657d4d50785ae0954ae4a364a0cb9b19/docs/轻量Hook与Markdown插件开发交付规范.md)
- **从宿主回读安装结果。** 旧插件从随包默认规则读取后，避免了旧用户副本遮住升级的情况。显式自定义文件仍按用户配置读取。共享 Skill 接入时同样核对实际入口路径，DSH 回读目标 Profile，Codex 区分市场登记、原生安装和 Hook 信任。卸载时按宿主和本插件入口的归属检查清理结果，保护共享市场条目和用户资料。[旧版开发与验证](https://github.com/Songyanglin-curious/agent-docs/blob/6465c475657d4d50785ae0954ae4a364a0cb9b19/docs/开发与验证.md) [本仓库安装与迁移](../../../README.md)
- **从用户的下载入口回验发行。** 版本、标签、附件名和安装说明保持一致。发布后从 README 使用的地址重新下载，核对 SHA-256、归档内容和版本。旧项目曾遇到中文附件名被 GitHub 规范化，完整安装包改用 ASCII 文件名。外层完整包另行核对哈希，内附校验清单用于独立安装包。[原交付规范](https://github.com/Songyanglin-curious/agent-docs/blob/6465c475657d4d50785ae0954ae4a364a0cb9b19/docs/轻量Hook与Markdown插件开发交付规范.md)
